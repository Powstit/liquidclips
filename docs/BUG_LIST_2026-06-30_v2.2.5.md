## Executive summary

This report now covers **9 real bugs + 1 feature request** (5 newly opened on 2026-06-30 during cold-onboarding + first successful-clip walkthrough on the v2.2.5 install).

Cold-install onboarding on a clean Intel Mac surfaced 6 issues across desktop-2 v2.2.5 and the linked account-app. Two are P0 user-visibility bugs that fire on every screen for every brand-new user (hardcoded "DANIEL · BETA" identity + a CSS grid that squashes Workstation stage labels into 1-character vertical columns). Two are P1 brand/data hygiene (old "Junior" loader residue across `account.liquidclips.app` page transitions + "Uncle Daniel" fixture fallbacks bleeding into live UI). One is a P2 cascade-risk in `Channels.css`. The sixth is a UX proposal from Daniel (deferred signup — let users in anonymously, only ask for account info on first paid action) — recorded as a feature request, not a bug. Estimated total fix time for the original 5 real bugs: under 3 hours. Deferred-signup feature is 2–3 days.

A follow-up walkthrough of a SUCCESSFUL clipping run on the same v2.2.5 install surfaced **4 additional bugs (BUG-007 → BUG-010)** in the post-complete Workstation UI. Daniel triggered a clip, the engine completed (CLIPS 6 · CLIPS READY visible in chrome), but the visible UI was dominated by the broken Stage Rail (7 squashed-letter vertical capsules) plus the inspector — and he literally couldn't find his clip cards. BUG-007/008/009 are all P0 success-path blockers ("I made clips and I can't see them"); BUG-010 is a P1 visual overlap with the persistent Kade fixture. These extend BUG-003 with the real root cause and reorder the Workstation main column so ResultsGrid lands above the fold post-complete.

### BUG-003 — Workstation stage labels squashed into 1-character columns

| | |
|---|---|
| **Severity** | P0 |
| **Visible at** | `My Clips` → Workstation view, stage progress strip |

**Symptom:** Stage labels render as letter-by-letter vertical text columns:

```
Pre / pa / rin / g / vi / deo       (Preparing video)
Pre / pa / rin / g / au / dio       (Preparing audio)
Tran / scri / bi / ng               (Transcribing)
Pic / ki / ng / cli / ps            (Picking clips)
Cut / ti / ng / cli / ps            (Cutting clips)
Ren / de / ri / ng                  (Rendering)
Mi...                               (Mixing or similar — truncated)
```

**Root cause:** CSS grid template gives each stage column ~12px width, forcing per-character text wrap.

**Sources to inspect:**
- `desktop-2/src/sections/editor/EditorSection.tsx` (and its `.css`)
- `desktop-2/src/design-os/routes/CreateClips.tsx` + CSS
- `desktop-2/src/design-os/routes/ClippingEngine.tsx`

**Recommended fix:** Find the offending `grid-template-columns` rule on the stage strip CSS, replace with `minmax(80px, 1fr)` (or similar), let the labels render horizontally.

This is the root cause of Daniel's "pages are black hard to read" complaint — the core user surface is literally unreadable.

### BUG-007 — Stage Rail dominates viewport after clips are ready

| | |
|---|---|
| **Severity** | P0 — blocks core flow ("I made clips and I can't see them") |
| **Visible at** | Workstation route (`My Clips` in sidebar) after engine completes |

**Symptom:** StageRail is meant to communicate pipeline progress DURING the run. Once `session.phase === "complete"` and `clipsReady > 0`, the rail shows seven "Complete" pills that consume the entire visible main-column height ABOVE the ResultsGrid. The actual clip cards (the user's whole reason for being there) end up below the fold and the user assumes nothing happened.

**Sources:**

| File | Issue |
|---|---|
| `desktop-2/src/design-os/engine/StageRail.tsx` | No dismiss condition based on `session.phase` |
| `desktop-2/src/design-os/routes/Workstation.tsx:~270` | StageRail mounted unconditionally inside `lc-ws-body-main` |
| `desktop-2/src/design-os/components/KadeIgnition.tsx:~30` | DOES dismiss when `clipsReady > 0`; StageRail should follow the same pattern OR collapse to a single-row chip |

**Recommended fix:** When `session.phase === "complete"`, collapse StageRail to a single one-line "✓ Pipeline complete · 3m 12s" pill (or remove entirely). Reserve the 7-tile detail view for the running phase.

### BUG-008 — Stage Rail tile labels wrap per-character (the "pages are black hard to read" complaint root cause)

| | |
|---|---|
| **Severity** | P0 — extends BUG-003 with verified root cause |
| **Visible at** | Same as BUG-007. Stage names render as letter-by-letter columns: "Pre / par / ing / vi / deo" etc. |

**Root cause analysis from CSS + component reading:**

- `desktop-2/src/design-os/engine/StageRail.css:4` declares `grid-template-columns: repeat(4, minmax(130px, 1fr))` — intended for a 4×2 wrap of 7 tiles.
- `desktop-2/src/design-os/engine/StageRail.tsx` renders 7 tiles via `STAGE_ORDER.map(...)`.
- The parent `lc-ws-body` (`Workstation.css`) uses `grid-template-columns: minmax(0, 1fr) 320px` — main column collapses to 0-min, so on a typical window the main column ends up ~360–420px wide.
- `.lc-stage-tile` has `min-width: 0` set explicitly, which lets the inner GlassCard shrink below content width.
- Net effect: tiles shrink to ~50px wide and labels word-break per character.

**Recommended fix:**

1. Change `.lc-stage-rail` to `grid-template-columns: repeat(auto-fit, minmax(140px, 1fr))` so tiles wrap naturally to multiple rows instead of squashing on one row.
2. Add `min-width: 140px` to `.lc-stage-tile` so the cell never collapses below readable width — letting the grid overflow horizontally (with scroll) is better than per-character wrap.
3. OR adopt BUG-007's collapse-on-complete fix and skip the layout problem entirely.

### BUG-009 — ResultsGrid (the actual clip cards) is below the fold, no way to discover

| | |
|---|---|
| **Severity** | P0 — Daniel literally said "i couldnt find or locate whats happening with my clips" |
| **Visible at** | Workstation route after a successful run. WorkstationFrame chrome shows "CLIPS 6 · SELECTED 0 · CLIPS READY" but the actual `ResultsGrid` clip cards are buried below KadeIgnition + StageRail + heartbeat-done pill in the main column. |

**Sources:**

- `desktop-2/src/design-os/routes/Workstation.tsx` main column render order:
  1. KadeIgnition (dismisses post-complete)
  2. StageRail (does NOT dismiss — see BUG-007)
  3. heartbeat-done "Clips ready" strip
  4. **ResultsGrid** ← THIS is what the user wants to see, but it's #4 in vertical order
- `desktop-2/src/design-os/engine/ResultsGrid.css:2` — grid is `repeat(auto-fit, minmax(190px, 1fr))` (fine, not the bug)

**Recommended fix:** Reorder the main column so ResultsGrid is FIRST when `session.phase === "complete"`. StageRail becomes a small status badge above the grid or disappears entirely.

## 💡 BUG-006 — Feature request: deferred signup (Daniel's UX proposal)

| | |
|---|---|
| **Severity** | UX request — not a bug |
| **Effort** | 2–3 days |

**Current flow:** Marketing → `/sign-up` form → email verify → `/sign-up/tasks` (persona) → `/dashboard` → download DMG → open app → activate

**Proposed flow:** Open app anonymous → ask "what should we call you?" → auto-create Whop account silently → use app on Free tier → only ask for paywall info on first paid action

**Implementation notes:**
- Desktop `LoginOnboarding.tsx` + `ClaimScreen.tsx` currently require a Clerk-issued license JWT before letting the user in
- Backend `junior-backend/app/desktop_connect.py` mints license JWTs against a Clerk user ID — would need an "anonymous trial" flow
- Whop has an auto-account API, but creating accounts without explicit consent is borderline TOS
- Cleanest version: let user use Free tier (100 clips, watermarked) WITHOUT signup; only ask for email + Whop link when hitting their first paid action
