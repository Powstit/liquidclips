### 2. Canonical owner change

**Before:** Every visible money value on the wallet + cancellation surfaces had a divergent read path — `useWalletLedger()` for balance, hardcoded `null` fallback for MRR (TODO), no canonical eligibility computation. Cancellation state was derived client-side from 3 legacy visual buckets with no lifecycle mapping. Referral attribution had no persistent recorder — the topic `referral_attribution_recorded` was documented but never fired backend-side.

**After:** `GET /me/money-rollup` (+ `GET /admin/money-rollup/{user_id}` mirror) is the ONE canonical source. `useMoneyRollup()` is the ONE hook. Every visible money value on WalletDetail reads from `moneyRollup.rollup.*`. INV-004 eligibility is enforced via `moneyRollup.rollup.withdraw_gates.*` (4 booleans). Cancellation surface has 6 canonical lifecycle states derived from authoritative backend fields (`User.subscription_status` + `withdraw_gates.affiliate_agreement_signed`). Referral attribution is persistent via `POST /affiliate/attribution/record` which writes to the LCOS event table (idempotent by `(topic, ts_ms, payload_hash)`).

**Duplicate writers removed:** the wallet's `mrrCents` computation no longer has a `TODO(backend)` placeholder — it now reads `affiliate_mrr_cents` from the rollup, which is computed from the canonical `eligible_referral_count()` service.

**Duplicate writers preserved (with justification):** `/me/wallet/summary` continues to serve the wallet ledger + campaign roster payload (the "denormalised" wallet page shape). It does NOT re-implement the rollup — the rollup is layered ON TOP for the summary numbers + eligibility. Same underlying data (`app.wallet` service), one canonical surface.

> **Wave contract rule:** the wallet-summary endpoint keeps its role as the campaign-list + activity-feed source; the rollup owns the money-value + eligibility contract exclusively.

### 9. Data-state cover

The rollup returns a MoneyRollup shape validated by `isMoneyRollupShape()`. Every field is a non-null integer or a nested `WithdrawGates` object (4 booleans). Any 200 with malformed shape is caught by the hook's shape validator and surfaces the `shape` error state.

Cancellation derives 6 canonical states from `(subscriptionStatus, paidUntil, agreementSigned)` triples:

| Input | Derived state |
|---|---|
| `trial` / `expired` / null · agreement OK | `never-subscribed` |
| `active` · agreement OK | `active` |
| `canceled` + paid_until > now · agreement OK | `cancelling-scheduled` |
| `canceled` + paid_until ≤ now (or null) · agreement OK | `cancelled-past-cutoff` |
| `refunded` · agreement OK | `refunded` |
| any status · agreement frozen | `chargeback` |
