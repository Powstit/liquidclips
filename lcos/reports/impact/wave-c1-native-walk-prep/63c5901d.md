## 7 · Known follow-ups (for Barrier 3 / C2 / C3)

1. **`window.__LCOS_BUS__` dev seam.** j005 preflight test attempts to fire `bus.emit("source:file-rejected")` from Playwright. If the bus is not exposed on `window`, the test degrades to a discovery check. C3 (or a small enabling patch) could expose the bus under `import.meta.env.DEV`.
2. **`window.__LCOS_DEV__.fakeRuntimeStaged(...)` hook.** j015 spec step 5 needs this to audit the pill copy without a real bundle. Without it, the copy-audit only runs if a real update happens to be pending. Consider adding it to `useRuntimeVersion.ts` under DEV.
3. **`data-update-copy` attribute.** Optional lightweight fallback for j015 spec: exposing the pill copy on a `data-update-copy` attribute on `UpdateBeacon` would let the walk audit copy even without a dev hook.
4. **`data-runtime-version` + `data-app-version` + `data-diagnostics-runtime-version`.** j015 spec step 8 reads these to prove parity. Confirm all four (TopHud, App root, Settings row, Diagnostics panel) actually surface them; add missing seams during Barrier 3 review.
5. **Fixture videos.** j005 doc references `desktop-2/tests/fixtures/walk-video-tiny.mp4` etc. C3 owns the fixture set; this doc does not create them.
6. **Backend `/me/publish/schedule` endpoint.** j007 spec step 8 probes this URL; C2 or backend owner should confirm the path (or update the doc).
