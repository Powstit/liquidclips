# Campaign Banner Generation Audit
### Pre-build investigation · NO BUILD

*Date · 2026-06-19 · Author · Claude · Audit scope only*

Daniel asked: can we auto-generate campaign banners after an agency creates a campaign, reusing Thumbnail Studio where possible, while keeping the result on-brand for Liquid Clips?

Findings + recommendation below. No code, no assets generated.

---

## 0.A · LOCK · 2026-06-19 · Marketplace Rectangle Template

**Decision locked by Daniel. Overrides anything below that conflicts.**

### Campaign banners are marketplace browsing cards for clippers.

They are NOT square thumbnails, vertical stories, custom agency ad layouts, or fully AI-generated posters. They exist so a clipper can scan a row of campaigns and instantly compare: company / brand · reward rate · funding trust · platform · status.

### Format

- **Aspect:** landscape rectangle · **16:9 or 3:2** (build picks one and pins it)
- **Surfaces consumed by:** campaign discovery grid, home reward carousel, campaign page hero, marketplace rows
- **One template, many campaigns.** The Liquid Clips frame is constant across every banner.

### Per-campaign dynamic fields (allowed to change)

1. **Background artwork** (AI-generated · scene only · see §0.B for what AI is allowed to render)
2. **Company / agency logo** (overlay slot · with fallback rules below)
3. **RPM value** (dynamic input · source hierarchy in §0.C)
4. **Platform pills** (from `targetPlatforms` · always drawn from brand icon set, never AI-rendered)
5. **Status pill** (Funded · Reward linked · Open in Whop — derived from `whop_reward_snapshot_status`, see §0.D)

### Fixed deterministic frame (constant across every campaign)

Drawn by Liquid Clips · never asked of the model:

- Company / agency logo slot
- RPM field (dynamic value, fixed pixel position + font + size)
- Funded pill OR Reward linked pill (mutually exclusive, derived state)
- **Powered by Whop** pill (always present when the campaign has a Whop reward connected)
- Liquid Clips watermark / wordmark
- Platform pills (optional row · only when `targetPlatforms` is non-empty)
- Typography · fixed across the marketplace · brand display font for title, Geist Mono for pills
- Badge placement · pinned positions · same across every campaign

### Marketplace consistency rule

> Every campaign banner should look like it belongs in the same Liquid Clips marketplace.
>
> The artwork gives the campaign personality. The frame gives Liquid Clips consistency.

## 0.B · Layer split (what AI does vs what LC does)

**AI is allowed to generate · ONLY artwork / background.**

**Liquid Clips renders deterministically · NEVER asked of the model:**

| Element | Why deterministic |
|---|---|
| Campaign title text | OpenAI text rendering is unreliable · typos = trust loss |
| RPM value (`$9 RPM`) | Must be exact · derived from snapshot or agency input |
| Company / agency logo | Either uploaded by agency or generated by LC's design skill · not by gpt-image |
| Liquid Clips watermark | Brand mark must be pixel-exact |
| Funded pill / Reward linked pill / Open in Whop pill | Derived from `whop_reward_snapshot_status` |
| **Powered by Whop** pill | Always present when reward connected · brand statement, not interpreted |
| Platform pills (YT / TT / IG / X) | Drawn from `/brand/decks/` icon set |
| Marketplace chrome (frame, divider lines, micro-pills) | LC visual language |

If the model renders any of the above by accident, the deterministic overlay covers it · the model is told explicitly "no text · no logos · no faces · empty negative space at top-left and bottom-right for overlay placement."

## 0.C · RPM source hierarchy (locked)

RPM is a **dynamic campaign input**, not a burned-in template field. Resolved by this order on every render:

1. **Whop snapshot RPM** — if `whop_reward_snapshot.rewardPerUnitAmount > 0` (the per-1k-views rate from the enriched Whop reward), use it.
2. **Calculated from Whop snapshot** — if `baseUnitAmount` is per-submission but the snapshot signals an RPM equivalent (e.g. via `bountyType` derivation), compute it. Only when reliable; flag in metadata as `derived`.
3. **Agency-entered RPM** — when no snapshot data, fall back to the RPM the agency typed during creation.
4. **Hidden / unavailable** — if none of the above resolve, the RPM slot is OMITTED from the overlay (no fake `$0 RPM`, no placeholder).

**Agency override is always allowed.** Even when snapshot RPM is present, the agency can correct it during creation or post-publish. Persist agency override on the row so it survives snapshot refreshes.

### Implementation requirements (for the build phase)

- `SponsoredCampaign` schema gains:
  - `rpm_value_cents` — the resolved RPM value cents (already exists as `rpm_cents`, reuse)
  - `rpm_source` — enum `whop_snapshot | derived_from_snapshot | agency_input | hidden`
  - `rpm_agency_override_cents` — nullable · when set, takes precedence over snapshot
- Agency creation flow (Step 1 or Step 2) gains an **RPM field** with snapshot prefill + manual override + "Hide RPM on banner" toggle.
- Banner compositor reads the resolved RPM value + source; renders the `$X RPM` slot when source ≠ `hidden`.

## 0.D · Status pill rules (locked)

The status pill on the banner is mutually exclusive · pick one based on `whop_reward_snapshot_status` + `whop_reward_state`:

| Condition | Pill rendered | Style |
|---|---|---|
| `snapshot_status == "enriched"` AND `whop_reward_state` ∈ {`live`, `funded`, `partially_funded`} | **Funded** | green-ish |
| `snapshot_status == "enriched"` AND `whop_reward_state == "capacity_reached"` | **Capacity reached** | amber |
| `snapshot_status == "enriched"` AND `whop_reward_state == "closed"` | **Closed** | grey |
| `snapshot_status` ∈ {`not_attempted`, `not_enriched`, `unreachable`} AND `whop_reward_url` is set | **Reward linked** | neutral |
| `whop_reward_url` not set | **Open in Whop** | neutral (CTA-shaped) |
| Legacy row · no Whop reward URL or id | (omit pill) | n/a |

**Hard rule:** if no snapshot, NEVER render `Funded` · use `Reward linked` (neutral). No fake green pills.

---

## 0.E · Company logo fallback rules (locked)

The company / agency logo slot is filled in this order:

1. **Agency-uploaded logo** when the agency has uploaded one (lands as a separate flow · `Agency.logo_url`).
2. **Agency initials** rendered in the brand display font, in a circular Liquid Clips chip · two-letter monogram derived from agency name. Deterministic, never AI.
3. **Liquid Clips placeholder** (the `made-with-liquid-clips.svg` wordmark in a compact pill) when no agency identity exists yet.

**Hard rule:** the model is NEVER asked to render the company logo · ambiguity in brand mark is a trust killer. Logo upload + initial-monogram are the only paths in v1.

## 0 · TL;DR

**Recommend D · Hybrid · AI background + deterministic Liquid Clips overlay.**

- Reuse `thumbnail_engine.generate()` for the background image only (no on-image text from the model).
- Compose a deterministic SVG/PNG overlay in the host (Tauri Rust shim or a Python PIL/Cairo function in the sidecar) with the Liquid Clips wordmark, campaign title, payout pill, platform cues, and "via Whop snapshot" qualifier.
- Cost: ~$0.07/banner (medium quality). Persistence: extend the existing `thumbgen_ledger.jsonl` with `kind: "campaign_banner"`. Persist banner files at `~/LiquidClips/campaign_banners/<slug>.png`.

Why not A/B/C:
- **A (reuse Thumbnail Studio directly)** — wrong aspect (Studio = 1536×1024 photoreal portrait), prompt is YouTube-thumb–shaped (subject-with-text), and on-image text from `gpt-image-1` is the unreliable part Daniel called out.
- **B (wrap Studio with CampaignBannerGenerator)** — closer, but inherits the on-image text risk. Banner copy MUST be exact (title typos = trust loss).
- **C (no AI · just compose brand assets)** — possible but loses the "every campaign feels unique" lift. The existing 8 deck PNGs would cycle into visible repetition once we have 20+ campaigns.
- **D (hybrid)** — the model owns mood + scene; LC owns text + brand mark. Text is always perfect, art always feels unique, brand is always present.

### 1.4 · Reusable for campaign banners?

Directly reusable:
- `_post_multipart` / `_post_json` helpers (the OpenAI HTTP plumbing)
- `_read_key` (API key resolution)
- `CancelledError` / `BillingLimitError` / `cancel_marker` pattern
- Cost table + ledger row shape
- The "background scene" portion of `build_prompt` (without the text-on-image clauses)

Needs adaptation:
- `build_prompt` is YouTube-thumbnail-shaped: bakes character + identity + "bold readable thumbnail text" into the model prompt. Banner generation should NOT ask the model for text at all.
- `references_dir` (face-crop identity) is the wrong identity primitive for a campaign banner — campaign banners are about the campaign's mood, not a recurring character. Re-purpose by leaving `references_dir` empty (model goes straight to `images/generations`).
- Default size 1536×1024 (3:2) is close to banner aspect; the existing brand banners are roughly 16:9 (1920×1080 equivalents). May want `1792×1024` (gpt-image-1's 16:9-ish option) for parity.

Available fields on a Campaign row (post-§8 patch):

| Campaign field | Where it lives | Used in prompt? |
|---|---|---|

| `description` (brief) | row.description | partial · mood keywords extracted, not pasted verbatim |
| `payoutRules` / `whopRewardSnapshot.baseUnitAmount` | row + snapshot | ❌ NEVER in prompt · deterministic payout pill |
| `campaign_type` (clip / coordination / affiliate / submission) | row.campaign_type | ✅ scene archetype lookup table |
| `whop_reward_snapshot.businessGoalType` | snapshot | ✅ scene mood (clipping / engagement / activation / growth) |

| `deadline` / `durationLabel` | row | ❌ NEVER in prompt · deterministic time pill |
| `brand` (sponsor name) | row.brand | partial · used for color/tone hint only · NEVER as on-image text |
| `mission_lane` | row | ✅ accent palette lookup |

### Two prompt layers · clean separation

**Layer 1 (AI · scene background only):**
```
Cinematic photoreal scene · {archetype based on campaign_type + business_goal} ·
{mood keywords extracted from description} · ink-on-fuchsia Liquid Clips palette ·
soft depth · no text · no logos · no faces · empty negative space at top-left
and bottom-right for overlay placement · 1792×1024 widescreen
```

The "no text · no logos · no faces · empty negative space" clauses are critical. The model gets to invent atmosphere, nothing else. Identity locking via `references_dir` is left EMPTY for banners (we don't want a character).

**Layer 2 (deterministic · LC overlay):**
- Top-left: `made-with-liquid-clips.svg` wordmark
- Center / lower third: campaign **title** in the brand display font (Geist or similar bold condensed), exact pixels
- Payout pill (bottom-left): "$X per submission" (derived from snapshot when present, mock payoutRules otherwise) + "via Whop snapshot" qualifier when applicable
- Platform badges (bottom-right): YT / TT / IG / X glyphs from `decks/` set, one per allowed platform
- Status pill (top-right): `badge-sponsored-mission.svg` / `badge-premium-mission.svg` / `badge-verified-campaign.svg` based on `placementQuality`
- Deadline pill (when present): "Xd left" timestamp in Geist Mono micro-pill

## 5 · Design rules (LC visual language)

Every generated banner MUST:

1. **Include the `made-with-liquid-clips.svg` wordmark.** Deterministic overlay · top-left. This is the brand stamp.
2. **Show the campaign title in EXACT pixels.** Deterministic SVG text · brand display font · never AI-generated text.
3. **Show a reward/payout cue.** Either `coin-stack.webp` glyph + payout pill, or a stamped `stamp-payout.svg`. Always derived from snapshot / payoutRules · never invented.
4. **Show a platform cue.** Platform badges from existing decks set · drawn deterministically.
5. **Stay in the Liquid Clips palette.** Ink (`#0B0B10`) + fuchsia (`#FF1A8C`) + paper · accent colors only from the existing brand kit (`src/index.css`).
6. **Honor `IG-012` (brand-kit drift gate).** Colors used in the overlay must reference the canonical tokens, not invent new hex values.
7. **NO fake money/luxury bait.** No stacks of cash, no luxury watches, no Lamborghini cliches, no clip-farm trash. The brand is "credible founder · documented work" not "make $5k a day."
8. **NO fake users / fake testimonials / fake screenshots.** Faces in the scene must be absent OR identity-locked to a known Liquid Clips character (Kade or Uncle Daniel). Default: no faces.

### 7.2 · Module layout

- **`desktop/python-sidecar/campaign_banner_engine.py`** (NEW · ~250 LOC) · pure-stdlib like thumbnail_engine. One public function: `generate(campaign, output_paths, *, config, cancel_marker)` returning the legacy result shape. Reuses `_post_json` / `_read_key` from thumbnail_engine.
- **`desktop/python-sidecar/banner_compositor.py`** (NEW · ~150 LOC) · the deterministic overlay step. PIL (already a sidecar dep for OpenCV adjacency) does the SVG/PNG composite. Alternative: cairo-svg, but PIL is simpler and already shipped.
- **`desktop/python-sidecar/sidecar.py`** · add 3 RPCs: `campaign_banner_build_prompt` (zero-cost preview), `campaign_banner_generate`, `campaign_banner_list`. Mirrors the thumbnail RPC trio for muscle-memory parity.

### 7.3 · Cost + rate-limit posture

- Default to **medium quality** ($0.07/banner).
- Agency can regenerate up to **3 times** within a publish session (gate at the backend). Beyond that, raise a "you've used your free banner regens" toast pointing at a future add-on.
- Sidecar already has `BillingLimitError` plumbing · plug it straight through.
- Cache by `(slug, title, description, snapshot_hash)` so identical re-publishes don't re-bill.

### 7.4 · Failure modes

| Failure | Behavior |
|---|---|
| OpenAI 429 / 5xx | Fall back to selecting from `/brand/decks/` preset PNGs + LC overlay only (Option C path). Campaign still publishes. |
| Content filter (no `data[]`) | Same fallback. Surface honest toast: "Background generation rejected · using a preset." |
| Cancellation mid-flight | Marker file pattern from thumbnail_engine. Agency can re-trigger. |
| Compositor exception | Skip overlay · log warning · ship raw AI background. Banner still publishable, marked `needs_review` for admin. |
| No API key configured | Skip AI entirely · use Option C deterministic-only path. Banner is on-brand even without AI. |

The architecture is **safe-by-construction**: a working banner ships even if every AI step fails. The AI is enhancement, not gate.

### 7.5 · What v1 explicitly does NOT do

- Custom fonts loaded from agency input (security · font upload is a real surface area)
- Brand-color customization per agency (locks to LC palette only · the brand stays Liquid Clips)
- Animated banners / video banners (`v1.5` consideration · much more cost)
- Logo upload from agency (deferred · current Liquid Clips wordmark IS the only logo on banners in v1)
- Social-share square + OG variants (deferred to v1.5 · canonical + card-thumb only in v1)
